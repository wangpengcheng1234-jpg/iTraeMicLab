# iTraeMicLab

macOS 实时麦克风监听台（图形界面）：把麦克风的声音低延迟地送到耳机，同时在人声增强、降噪与噪声门上做实时处理。

> 纯本地运行，不联网、不录音、不上传。只有单文件 SwiftUI 源码，无需 Xcode。

## 功能

- **实时返听**：输入 → EQ → 压缩/扩展 → 输出，延迟可压到约 4 ms（引擎侧）
- **设备选择**：自动列出可用输入/输出设备，2 秒轮询热插拔
- **耳机优先**：默认选非扬声器输出；选到扬声器会弹窗提示回授啸叫，取消可回退
- **处理链**：高通、2.6 kHz 人声存在感、6.5 kHz 空气感、5 kHz 以上降噪衰减；压缩器 + 向下扩展器（噪声门）
- **三档预设**：关 / 轻 / 强，另有降噪、噪声门、门限、高通、总增益细调
- **超低延迟模式**：输出采样率对齐输入 48 kHz（去掉重采样）+ 64 帧缓冲
- **电平表**：PEAK 读数、44 段 LED 电平条、10 秒历史
- **运行参数**：当前输入/输出、图采样率、缓冲帧、估算延迟、处理链
- **底噪自检**：静音 2 秒测 RMS，给出门限建议
- **事件日志**：启动、切换、设备异常、引擎 watchdog 都会记录

## 系统要求

- macOS 14.0 或更高
- Apple Silicon 或 Intel（构建脚本用 `uname -m` 自动取架构）
- 构建需要 Command Line Tools（`xcode-select --install`），**不需要完整 Xcode**

## 构建与运行

```bash
git clone <本仓库地址>
cd iTraeMicLab
chmod +x build-miclab.sh
./build-miclab.sh
open iTraeMicLab.app
```

首次点「开始监听」时，系统会请求麦克风权限，选择允许。

如果双击提示「来自身份不明的开发者」：右键 → 打开 → 打开。

## 使用

1. **01 / 输入源**：默认优先选择名字含 `USB` 的输入设备，没有则取第一个可用输入。
2. **02 / 监听输出**：默认选第一个非扬声器设备；建议用耳机。
3. **03 / 处理链**：先选档位，再按需调整降噪/噪声门/门限/高通/总增益。
4. 点 **开始监听**；右侧看电平与运行参数。
5. 环境安静时点 **底噪自检 (2s)**，按提示调门限。

> 把鼠标停在任意设备选择、开关、滑块、按钮或读数上，都会弹出该功能的用途与设置建议。

底噪偏大时的推荐设置：

| 项 | 建议 |
|---|---|
| 档位 | 轻 |
| 降噪 | 开 |
| 噪声门 | 开 |
| 门限 | -50 ~ -45 dB |
| 高通 | 100 Hz |
| 超低延迟 | 需要更低延迟时再开 |

## 工作方式（重要）

AVAudioEngine 的输入/输出节点**无法**单独绑定设备（实测设置 `kAudioOutputUnitProperty_CurrentDevice` 要么静默不生效，要么返回 -10851；对输入节点设置还会 -10875 启动失败）。因此本应用的做法是：

1. 临时把**系统默认输入/输出**切到目标设备；
2. 重建整个音频引擎；
3. 停止监听或退出时恢复原来的默认设备。

**副作用**：监听期间其他 App 的声音也会走到你选的输出设备。强制结束进程（强制退出/崩溃）不会自动恢复，需要在「系统设置 → 声音」里手动改回。

### 超低延迟

以下为某 96 kHz 输出设备下的示例（实际数值随设备与缓冲设置变化）：

| 模式 | 图采样率 | 缓冲 | 引擎侧估算延迟 |
|---|---|---|---|
| 普通 | 96000 Hz | 256 帧 | 约 6.7 ms |
| 超低延迟 | 48000 Hz | 64 帧 | 约 4.0 ms |

以上为引擎侧估算值，不含麦克风自身可能存在的无线传输延迟。总延迟 = 麦克风传输 + Mac 处理 + 耳机输出。

## 底噪说明

不同设备、接口与供电环境下的底噪差异很大，**没有通用绝对值**。启动监听后，在安静环境点「底噪自检 (2s)」，用测到的 RMS 判断当前链路：

| RMS（dBFS） | 参考判断 | 可尝试 |
|---|---|---|
| > -50 | 偏大 | 开降噪 + 噪声门、启用超低延迟、换 USB 端口/缩短线材 |
| -65 ~ -50 | 常见范围 | 开噪声门即可明显改善安静时的听感 |
| < -65 | 良好 | 保持默认设置 |

> 表中数值只是经验参考，实际以设备手册或自己的听感为准。

如果同一套设备在别的系统上听起来更安静，通常是那边驱动层做了 APO 处理（降噪 / 自动增益 / 回声消除），而 macOS 对普通 USB 音频类设备是直通、不做 DSP。所以底噪多来自设备 ADC 与供电链路，而不是 macOS 额外加进去的。

排查顺序：
1. 开降噪 + 噪声门，门限从 -50 逐步上调到能盖住底噪又不切人声的位置。
2. 开超低延迟，去掉输入/输出采样率不一致时的重采样。
3. 总增益调回 0，避免用增益去「补音量」。
4. 换一个 USB 端口、避免使用拓展坞或延长线，排除供电/地环路干扰。
5. 关机状态下再自检一次，可区分噪声来自拾音端还是 USB 链路。

## 常见问题

**双击报「不能与此版本的 macOS 配合使用」**

`swiftc` 默认会把 `minos` 写成 SDK 版本（如 28.0），高于你的系统版本。构建脚本已用 `-target $(uname -m)-apple-macos14.0` 锁定，确认 `vtool -show-build-version iTraeMicLab.app/Contents/MacOS/iTraeMicLab` 显示 `minos 14.0` 即可。

**改了代码，但打开的 App 还是旧界面**

本应用是本地构建，**没有自动更新**。`./build-miclab.sh` 重新打包后，需要先完全退出正在运行的实例（⌘Q），再双击打开；旧实例还活着时，双击只会把它切到前台。窗口底部会显示类似 `v1.3 · build 2026-11-02 22:30` 的构建信息，可据此确认是不是最新构建。

**监听开着却没声音 / 电平 -90**

- 看日志是否提示「2 秒内没有收到音频数据」——多数是麦克风关机或休眠。
- 确认输出设备没被系统改回扬声器。

**切换输出后声音没跟着走**

这是预期行为：切换会触发「停止 → 重建 → 启动」，等日志出现「重建链路」后再看电平。

**想送到 OBS / 会议软件**

本应用只做本机返听，不能把处理后的音频交给其他 App。需要装 BlackHole 之类虚拟声卡做路由。

## 已知限制

1. 监听期间会临时改系统默认输入/输出；强制退出不会恢复。
2. 只做实时返听，不做虚拟声卡路由。
3. 部分无线麦克风关机后会停止数据流，App 会提示无音频数据。
4. 本地 ad-hoc 签名；重新编译后如再次询问权限，重新允许即可。
